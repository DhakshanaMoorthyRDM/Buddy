# 🧑‍💻 Buddy — Project Master Plan

## 1. What is this project?

**Buddy** is a personal Windows desktop AI companion.

The idea is not just to make a chatbot with a character attached.

The long-term goal is:

> **A small autonomous desktop companion that lives on your Windows desktop, has a personality and visual presence, can see/hear/speak when permitted, remembers things, reacts to what is happening, and can interact with your computer through controlled tools.**

Think of it as:

```text
        ┌─────────────────────────────┐
        │          BUDDY              │
        │                             │
        │   🧠 AI / Personality       │
        │   👀 Vision                 │
        │   👂 Hearing                │
        │   🗣️ Voice                  │
        │   💾 Memory                 │
        │   😊 Emotions               │
        │   🛠️ Tools                  │
        │   🔐 Permissions            │
        │   🖥️ Windows interaction    │
        │                             │
        │        [ Chibi ]            │
        └─────────────────────────────┘
```

But we're deliberately building it **from the bottom upward**, rather than trying to make everything at once.

# 3. Why we're using layers

We deliberately avoided making every expression a completely different character image.

Our structure is:

```text
BODY
  +
HEAD / HOOD
  +
EYES
  +
CHEST CORE
```

So we can independently change:

```text
Eyes
├── Open
├── Closed
├── Half closed
├── Looking left
├── Looking right
└── Future expressions

Chest
└── Glow / pulse

Body
└── Future poses / animations

Head
└── Remains stable
```

This is important because otherwise blinking would require swapping the entire character.

# 9. Scaling problem — solved

We had a problem where the breathing animation and character scaling both wanted to use CSS `transform`.

We fixed that by introducing:

```text
character-stage
      ↓
character-scale
      ↓
character
```

Current conceptual structure:

```text
132 × 132
character-stage
      │
      └── 627 × 627
          character-scale
              │
              └── character
                  ├── body
                  ├── head
                  ├── eyes
                  └── chest
```

`character-scale` handles the permanent scale.

`character` handles animation.

This prevented the breathing animation from overriding the character scale.

# 11. Dragging

This was the most recent major milestone.

Initially we used:

```text
CSS -webkit-app-region: drag
```

But that made the **entire 132×132 rectangle draggable**.

That wasn't acceptable.

We wanted:

```text
       132×132
┌─────────────────┐
│ transparent     │
│       🧑        │ ← draggable
│ transparent     │
└─────────────────┘
```

So we built a pixel-based hit-test.

---

# 12. Pixel hit testing

We created a hidden:

```text
627 × 627 canvas
```

and drew:

```text
BODY
+
transformed HEAD
```

onto it.

Then we inspect:

```ts
hitContext.getImageData(x, y, 1, 1).data[3]
```

The final channel is alpha.

Therefore:

```text
alpha === 0
    ↓
transparent

alpha > 0
    ↓
Buddy exists here
```

This lets us determine whether the mouse is actually over Buddy's visible pixels.

---

# 13. Native click-through

This was the tricky part.

The requirement was:

> If I click transparent space around Buddy, Windows should receive the click instead of Buddy.

We discovered that normal browser hit testing isn't enough.

So we integrated Electron:

```js
win.setIgnoreMouseEvents(...)
```

with:

```js
forward: true
```

and global cursor tracking.

The current architecture is:

```text
Windows cursor
       ↓
Electron
       ↓
global cursor coordinates
       ↓
renderer
       ↓
627×627 alpha mask
       ↓
is Buddy visible here?
       │
       ├── NO
       │    ↓
       │  Electron ignores mouse
       │    ↓
       │  application underneath receives click
       │
       └── YES
            ↓
          Electron interactive
            ↓
          Buddy receives input
```

This is now **working**.

# 14. Fast dragging

We also found another problem.

Normal dragging worked, but if you dragged Buddy extremely quickly:

```text
mouse
  ↓
leaves 132×132 window
  ↓
renderer stops receiving mousemove
  ↓
Buddy stops following
```

We fixed that by moving the actual drag movement into Electron.

Electron now tracks the **global Windows cursor**.

Conceptually:

```text
Mouse down on Buddy
        ↓
Electron starts dragging
        ↓
global cursor tracking
        ↓
cursor delta
        ↓
move BrowserWindow
```

Therefore the cursor can leave Buddy's window and Buddy still follows.

You tested this with fast dragging and confirmed:

> **It's working fine.**

That is our latest completed technical milestone.

Each major layer should work before we add the next.
